# ADR-0097: Windows Installer Artifact Gate

> Status: implemented  
> Owner: desktop maintainers  
> Date: 2026-08-23  
> Scope: `desktop/installer-artifact-smoke.ps1`, Windows CI artifact upload

## Context

The Windows packaging job invokes Tauri installer generation, but a build can
appear successful while MSI/NSIS outputs are missing or absent from uploaded
artifacts. Installer identity must also remain aligned with the release
manifest's SHA-256 records.

## Decision

Formal installer mode runs a dedicated artifact smoke after packaging. The gate
requires at least one non-empty MSI or NSIS executable, requires a neighboring
release manifest, and compares every installer size-independent SHA-256 digest
and relative path with the manifest. Windows CI uploads MSI and NSIS files in
addition to the portable ZIP, desktop executable, sidecar, and manifest.

The gate does not install or uninstall software. Installation, shortcut,
sidecar resource resolution, and `/readyz` GUI verification require an
interactive Windows runner and remain a separate validation stage.

## Consequences

- Missing installer output fails the formal package job instead of producing a
  misleading release artifact.
- CI retention includes both installer families when generated by Tauri.
- Portable and no-installer modes remain valid local development gates.

## Verification

- PowerShell parser validation covers the new gate.
- Normal Windows CI invokes the gate after the existing artifact and runtime
  smoke checks.
